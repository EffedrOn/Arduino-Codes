MEMORY
	Each memory is organized into memory cells-bits
	Bits are grouped into words of fixed length:
		-1, 2, 4, 4, 8, 16, 32, 64 and 128 bits
	Each word can be accessed by a binary adress
	
	Physical view:
		-2D ARRAY
			-row x column(much faster access)
			-Select, access, deselect row
			-Timing:
				CAS(tCL) = Column Access Strobe
				tRCD = Row Address to Column Address delay
				tRP = Row Precharge
				RAS	(tRAS) = Row Active Time
	Signed numbers:
		2s complement
			Bitwise negation +1
			one 0
			Compatible with unsigned aritmetic
			Asymetric range
	Floats:
		IEEE 754 floating point numbers
			Hidden bit convention
				Single precision
				Double precision
			Exponent (unsigned)
				Bias (SP = 127, DP = 1023)
			Value
				V = (-1)^(sign) x significand x 2^(exponent - bias)
				significand = value part, much bigger than the exponent

			1bit	8bits					23bits
			|sign|		exponent		|			Mantissa			|

	Endianess
		Big endian
			MSB first
		Small endian

	Data alligment 
		inner padding:
		-Modern CPUs require data in memory  aligned to their size
			e.g, integer (4B) must have address aligned to 4

		-Adresa na ktorej je ulozeny nas typ napr 4B integer musi byt delitelna 4!!!!
	
		Outer padding:
			-Struktury su vzdy aligned na nasobok najvavcsi typ ktory obsahuje

	Memory Managment:
		Global variables
			-Allocates at the beginning, fixed place, released when application terminates
		Local variables, function arguments
			-Allocated at the stack by 	shifting stack pointer
			-stack growth, reallocation
		Dynamically allocated variables

			-ked nepotrebujem uz pouzivanu pamat musim ju uvolnit
			
	Memory allocation
		-Task
			locate a block of unused memory of suficient size
			allocate portions from a large pool of memory	
		-Lifecycle
			Allocate a block
				different strategies, allocators
			Use the block

				explicitly, garbage collector

	Fragmentation
		Internal
			allocated more memory than needed in a block
		External
			Free memory is separated into small blocks and 	interspersed	by allocated memory

	Dynamic memory allocation
		Contiguous  allocation of variable size
		Free block evidence
			-Linked list
			-Bitmap
				each bit represents a block of a fixed size

	ALLOCATION ALGORITMS
		First Fit
			Start from the beginning, find the FIRST free space big enough to accomodate the required block
		Pros: fast,simple
		Cons: can divide larger blocks

		Best Fit
			Starts from the beginning, find the smallest space big enough.(scan the whole heap)
			Pros: keeps large blocks
			Cons: slower, creates many tiny blocks
			
		Next Fit
			Like the first fit but starts from the last position(position of last allocation)
			Pros:fast,doesnt make fragmentation on the start of the heap
			- this is the one usually used
		Worst Fit
			Start 	from the beginning, find the smallest space big enough
			Cons: divide large blocks
			-nepouzivany, total napicu

		napr: malloc nepouziva ziaden z tychto algoritmov ale nove komplexnejsie


	BUDDY MEMORY ALLOCATION
		all blocks of 2^n size
			address aligned to 2^n
		Find the smallest 2^n block fitting the required size	
			-list of free blocks lists with fixed sizes 2^n
		If there are no small blocks, create them by dividing the larger blocks
			-buddies
				find the budddy address by XORing my address with the block size
		Merge blocks  back when both buddies are free
		significant internal fragmentation


	CACHE
		HW or even SW
			-structure holding data
				data loads/computations(for the first time) is slow/expensive
				Future request for that data can be served faster	
				Limited(fixed) size

			-Generic	cache operation
				Make a request for data
				Are data placed in a cache??
				ak su vrat ich ak nie preved pomale vypocitanie potrebneho/access

		Cache  in CPU
			HIDES MEMORY LATENCY	
			Based on the locality of reference
				Teoria: most applications require the same small part of memory all over again
			CPU cache operation
				make a request for data in memory
				Are data placed in a cache? Looks in all levels of cache in the cpu from the fastest L1 to slowest LLC
		
				If they are, return them to the execution unit in a CPU core, otherwise do a full memory access

			Terminology:
					Cache line	/entry
						Caches are organized in a lines
							usual size is about 64B
							aligned
							aj ked potrebujem len jeden byte z cache dostanem cely 64B blok
							
					Cache hit
						success
						request served from the cache
						Succes rate is about 97%
					Cache miss
						Data not found in cache hierarchy, do a full memory access
						Load data from the memory to a cache line
								select either a free cache line or select a victim cache line
								store modified cache lines back to the memory
					Cache line state
						-MESI protocol
						each cash line is acompanied by 2 bits = 4 states
						state tells something about state in the cache
						base for the comunication


			ASOCIATIVE MEMORY (important)
					ulozene kusky pamate RAM do cache
	
					uses KEYS and VALUES
					requesting values by their keys
					
					very fast
					content based addressing
					used in CPU caches
		
		NUMA
			multiprocesors
				SMP = Symetric Multiprocessing
				NUMA = Non-Uniform Memory Access

		MULTITASKING
			-Cooperative
				Unit of scheduling must explicitly  and voluntarily yield control
				All processing must cooperate
				Scheduling in OS reduced on starting the process and making the context switch after the yield
					OS does not indicate context switch
			-Preemptive
				Each running unit of scheduling has assigned TIME SLICE somewhere between miliseconds and half a second
				OS needs  some external source of interrupt (HW timer)
				
				If the  unit of scheduling consumes whole time-slice 	
					interrupted by the external source
					cahnged to READY state
					OS will make a context switch
		
		OBJECTIVES of scheduling
				maximize/optimize CPU utilization (based on workload)
				Fair allocation of the CPU
				Maximize throughput
					number of processes that complete their execution per unit time

		PRIORITY of scheduling
			Priority
				A number expresing the importance of process
				Unit of scheduling with greater priority should be scheduled before(or more often than) unit of scheduling with lower priority
				The priority of the process is the sum of a static priority and dynamic priority
					Static priority
						Assigned at a start  of the process
							Users hierarchy importance
					Dynamic priority
						casom proste rastie priorita
						Adding fairness to the scheduling
						Once in a time, the dynamic priority is increased for all READY units of scheduling
						The dynamic  priority is initialized to a 0 and is reset to 0 after the unit of scheduling is scheduled for execution

		SCHEDULING ALGORITMS:
			NON-PREEMPTIVE
				First Come, First Serve (FCFS)
					Single FIFO queue
					A process enters the queue on the tail, the head process is running on the CPU
					ptm vymazane z qeue

				Shortest job first 
					Maximize throughput
					Expected job execution time must be known in advance
				
				Longet job First
		
			PREEMPTIVE
				Round Robin:
					Like FCFS (but preemptive)
					single queue
					Each unit of scheduling has an assigned time slice
					If the unit of scheduling consumes the whole time slice or is blocked, it will be assigned to the tail of the queue

				Multilevel Scheduling:
					Multiple queues
						time-slice defined by queue
					If unit of scheduling consumes the whole time-slice, it will be assigned to the LOWER queue
					If the unit of scheduling blocks before consuming the whole time-slice, it will be assigned to the HIGHER queue
					Schedule head unit of scheduling from the highest non-empty queue
						
					Top level queue ma maly time-slice a naopak bottom-level ma velky

					CPU prechadza top to bottom a najde prvy neprazdny queue a vyberie z neho unit of scheduling
		
				Completely fair scheduler (CFS)
					default scheduler for linux
					implemented in linux kernel
					Processes are in red-black tree
						indexed by execution time (usporiadane)
					Maximum execution time
						Time-slice calculated for each process (e.g by priority)	
						The time waiting to run divided by the total number of processes
					Scheduling algoritm:
							The leftmost node is selected (lowest execution time)
							If the process completes its execution, it is removed from 	scheduling
							If the process reaches its maximum execution time or is somehow stopped or interrupted, it is reinserted into a 								tree based on its new execution time

				ADDRESS TRANSLATION
					Steps for address translation
						Take page number from VA and keep offset (separately)
						Check TLB for mapping
							if exists, retrieve frame number otherwise coninue
						Go through the page table
							Divide page number into multiple PT indices
							index 1st level PT
								If there is no mapping for 2nd level PT, raise page fault exception
								Retrieve PA for 2nd level PT and continue
							Go through all levels of PTs
								if there is no mapping in any PT level, raise page fault exception
								if all PT levels are mapped, retrieve frame number
							Save retrieved mapping to TLB

						Update A(ccessed)=set when read and D(irty)=set when written bits in page table/TLB
						Assemble PA by "gluing" the retrieved frame number and the original offset from VA	
				
				
				PAGE FAULT EXCEPTION HANDLING
					An instruction raises the page fault exception
					OS interrupt handler
					Determine the cause of the fault
						Unathorized access
							out of allocated virtual space, store to R/O page, access to kernel memory
						Valid adress but not mapped	
					Create mapping
						find a free frame
							either there is one unoccupied
							or find a victim (for swapping)
								page replacement algorithms
								save dirty victim frame
								remove mapping from TLB
						load content to the free frame
						construct/fill corresponding page tables
					Return back from handler and retry the instruction
		
				
				PAGE REPLACEMENT ALGORITHMS
					Any situation, when you need to find a victim from a limited space
					Frames, TLB, cache

					Optimal page algorithm
						Replace the page that will not be used for the longest period of time
						lowest page-fault rate
						Theoretical, we do not have an oracle for foretelling the future 

					CLOCK algorithm
						Frames organized in a circular manner
						Clock hand points to the next frame to replace
						Each page has A(cessed) bit
							A is the accessed flag which is set to 1 whenever the page is touched by HW
						If the frame has A != 0, set A = 0 and advance the hand
						If the frame has A == 0, select this frame

					NRU (Not Recently Used)
						Each page has A(ccessed) and D(irty) bits
						Clears A bits periodically (e.g, once a minute)
							Bit D is not touched 
						Uses A and D bits to classify frames into four classes
						Selects a random frame from the lowest non-empty class

					LRU (Least Recently Used)
						Uses the recent past as a predicition of the near future
						Replaces the page that has not been referenced for the longest time
						Existing HW IMPLEMENTATIONS
							Cache
							Bit matrix
						SW implementation
							Move-to-front algorithm
								can be implemented by linked list or heap data structure
							Too complicated and space consuming
							Approximation algorithms exists
					
					NFU (Not Frequently Use)
						Rough approximation of LRU
						Each frame has a counter (typically small, several bits)
						Periodically scan page table and increase the counter for a frames with A==1
							always clear A
						Select the frame with lowest counter
						Problems
							newly occupied frames may be swapped before the get used
							Frames that were previously jeavy used will never be selected
						Aging
							periodically divide counters by 2 (i.e , shift by 1)
					
					ADVANCED PAGING
						Shared memory
							part of a virtual memory space shared amongst processes
								the block is probably placed on different starting virtual address
						Memory-mapped files
								File as a backing store for paging
								Direct access to the file content using CPU instructions
								Problems with file size and with appending data
